## 固定的推理合同

每个样本由 ROI 内 400 个事件形成 `2×96×128` 双极性计数图，在两个内部
逻辑步 `t0,t1` 完整重复。每个新样本开始前清空全部膜状态；两个逻辑步不是
两个 FPGA 时钟，也不是两批新事件。

卷积层 L1～L5 为 `Conv(no bias)→BN→MaxPool→LIF`，L6～L8 为
`Conv(no bias)→BN→LIF`。随后是 `480→60→12` 两个脉冲全连接层；H2 的两个
时间步脉冲先精确除以 2，再送入无 bias 的 `12→2` 连续读出。

将 BN 输出和阈值归一化后的当前步电流记为 `I_t`，逐神经元语义为：

```text
u_t = 0.75 * v_(t-1) + I_t
s_t = max(floor(u_t), 0)
v_t = max(u_t - s_t, -1)
```

`s_t` 是非负整数 MultiSpike 计数，没有由模型定义的有限上界。L1/L2 在
`t0→t1` 边界清空膜，其他层保留；因此 L1/L2 对两个重复输入必须产生完全
相同的输出。L1/L2 的 `t1` 后残余膜没有消费者，硬件无需物化。训练使用的
PeriodicExponential surrogate gradient 不进入推理电路。

对每个输出通道，BN、阈值和无 bias 卷积可折叠为：

```text
a  = gamma / (sqrt(running_var + eps) * theta)
W' = a * W
b' = (beta - gamma * running_mean / sqrt(running_var + eps)) / theta
```

所以原卷积没有 bias，不表示电路没有逐通道常量 `b'`。前五层仍必须保持
“完成本步卷积与归一化电流→MaxPool→LIF”的顺序。

## 公平对照与计算复用

建议按三档分别实现和报告：

| 名称 | 调度 | 两步浅层计算 | 跨步状态 | 用途 |
|---|---|---|---|---|
| FS-TM | `t0`整网后`t1`整网 | 都执行 | L1～H2，共45,000 | 全状态基线 |
| SL-TM | 与FS-TM完全相同 | 都执行 | L3～H2，共8,136 | 单独测状态删除收益 |
| SL-HYB | `t0`算浅层并缓存边界，`t1`复用 | 复用L1/L2前缀 | L3～H2，共8,136 | 单列重复输入优化 |

全状态模型也应获得重复输入允许的优化：它可以缓存 L1 的当前步输入电流，
但因 L1 膜保留，不能直接复用 L1 脉冲。最终无状态模型的 L1、L2 输出均在
两步相同，可选择两个复用边界：

- 缓存 L2 脉冲：容量为 `12,288*b_s` bit，即 `1,536*b_s` byte；若脉冲计数
  为 8 bit，需要 12 KiB。
- 缓存 L3 的 Pool 后、LIF 前电流：容量为 `4,608*b_i` bit，即
  `576*b_i` byte；若电流为 16 bit，需要 9 KiB，并能跳过第二步从输入到
  L3 电流生成的全部计算。

L3 电流缓存小于 L2 脉冲缓存的条件是 `b_i < (8/3)*b_s`。位宽未冻结前，
不能只凭示例确定边界。

整网单步稠密 Conv＋Linear 为 10.391M MAC，两步为约 20.781M MAC。缓存 L3
电流可省去第二步 L1～L3 的 7.963M 稠密 MAC。按现有脉冲活动估算，原始两步
SynOps 为 7.290±0.447M；缓存 L2 脉冲后约 6.476±0.368M，缓存 L3 电流后约
5.196±0.258M。这些数值不是周期、功耗或 FPGA 实测。

纯粹按层处理两个时间步可以把每层状态局部化，但会引入两步激活缓存，并使
45,000→8,136 的物理 RAM 对比依赖另一套映射。它可作为 dataflow 敏感性
分析，不适合作为唯一的全状态/无状态比较。

## 空间计算与首版核心

一周版本建议使用规则的分块稠密共享卷积核心，首个候选输出通道并行度为
`P_OC=8`。原因是它能先建立确定的周期、RAM 和时序账，并覆盖真实的
L1→L2→L3 尺寸。若直接把 SynOps 映射成稀疏 scatter，仍需提供部分和/当前
累加器、地址路由和输出初始化；折叠常量还可能使没有输入脉冲的位置发放，
因此不能假设“无事件就完全不访问输出”。稀疏版本可在规则核心正确后评估。

候选模块边界为：

```text
input loader
  -> scheduler
  -> shared conv + folded affine + pool
  -> MultiSpike LIF
  -> ping-pong activation RAM
  -> H1/H2 + temporal mean + readout

state RAM: FS存L1～H2；SL存L3～H2
perf monitor: 周期、状态读写、激活读写、权重读、有效累加
```

可综合核心保持器件无关，另设 `core_synth_top`；AUP-ZU3 回放另设
`aup_zu3_replay_top`，以后需要 PS/AXI 时再加 wrapper。这样行为仿真不依赖
板卡文件，综合和布局布线才绑定具体器件。

目标板为 RealDigital AUP-ZU3，器件固定为 `XCZU3EG-2SFVC784E`。本阶段最初
建议用板载100 MHz PL时钟起步；后续完整RTL的Vivado OOC目标已锁定5 ns，

[AUP-ZU3页面](https://www.amd.com/de/corporate/university-program/aup-boards/realdigital-aup-zu3.html)

[官方板卡仓库](https://github.com/Xilinx/AUP-ZU3)当前参考工程使用 Vivado
2024.1。Vivado Basic 支持 XCZU3EG。

2026-10-06进入本阶段时服务器尚未发现Vivado或开源RTL工具；随后已建立独立
环境并完成Icarus、Verilator和Yosys验收。当前服务器仍无Vivado。器件相关综合、
实现和时序需要有Vivado的机器，上板只承担最后的真实回放验证；当前目标不需要
ASIC EDA。

## 验证产物与验收条件

定点参考需输出 NPZ、逐端口 MEM 和 manifest。manifest 至少记录 checkpoint、
configuration、缓存和各向量的 SHA-256，张量布局、定点格式、舍入、饱和、
alpha0.75 计算顺序，以及 FS/SL 模式。首轮向量建议使用 16 个 validation 样本，
再加全零、边界值和最大输入等合成样本。

RTL 与参考的验收条件为：

1. 每层脉冲、保留膜和最终 gaze 定点结果逐项 bit-exact；
2. FS/SL 在相同位宽、PE 数、时钟和 RAM 推断方式下比较；
3. 状态读写计数与 45,000/8,136 元素账一致，其他 RAM 流量分项报告；
4. 对 `xczu3eg-sfvc784-2-e` 完成综合和布局布线，100 MHz 下
   `WNS>=0`、`WHS>=0`，无未约束路径和 error DRC；
5. 资源报告列 LUT、FF、BRAM、URAM、DSP，延迟列周期与换算时间；功耗若只有
   工具估计，明确输入活动和估计范围。
